# 三上3.2《各种各样的运动》· 运动轨迹观察器

访问：https://mutiwangn.github.io/AI-html/三上3.2各种各样的运动/

`index.html` 为当前 v3.1.1 红点优先版入口；`运动轨迹观察器_v3.1.1.html` 为可独立保存的单文件版本。旧版 v1、v2、v3、v3.1 均保留，不覆盖历史文件。无第三方脚本、无需账号或 API 密钥。

### v3.1.1 修补

选目标时，最小选框改为分析画面内的 6 × 6 像素，不再要求宽高都占视频的 2.5%。因此竖屏中约 20 × 11 像素的细小红贴纸可以正常圈选，纯点击和过小误触仍会被拒绝。红点自动检测、追踪和完整物体叠影算法保持不变。

## v3.1：红色标记优先

- “轨迹”页无需先手工标点，点“找红点”即可寻找画面里的小红贴纸；暂停时也可点选红贴纸，程序会吸附到它的颜色加权中心。观察对象是红色标记的中心，不是点击处对应的一个材料质点。
- 追踪优先使用红色色相、饱和度、连通区域、大小和旋转不变形状证据。支持相邻帧红点位置大幅变化，不局限于原来的小模板框。多个相似红点无法可靠区分时要求手动选点或圈选，不自动选择最大的红物体。
- “叠影”默认“自动（红点优先）”：有明确红标记时，只把真实红标记像素按等时间间隔留在原画面中，并显示“红点位置 · 原画面坐标”。这不是整只陀螺的抠图叠影，不会把蓝色物体、选框背景或虚构的圆点复制过去。要观察完整物体，可在设置中选择“完整运动物体”。
- 红点模式不依赖背景纹理，也不启用背景防抖；灰色桌面不再阻挡红点识别。请固定手机，因为手机移动也会改变原画面中的点位。完整物体模式仍保留 v3 的背景对齐与主体分离。
- 标记出画、遮挡、过于模糊或身份不能确认时停止，不补画圆周，也不在重现后擅自接回。自动找点和追踪均可撤销；取消任务不会留下半次结果。
- 快速旋转会产生时间混叠：点列和箭头只表示取到的样本先后，不能仅据稀疏点判断真实转向、圈数或转速。拍摄后慢放不能恢复未拍到的中间位置；需要更清晰证据时，应增加光线、放慢转动，或导入系统相机的高帧率录像。

## 拍摄、叠影、轨迹

- 手机竖屏大画面，底部固定“拍摄 / 叠影 / 轨迹”；横屏自动调整操作区。
- 拍摄：首页直接选择“普通 / 慢动作 / 延时”。圆形按钮先打开预览，再点开始，录制中再点停止；也可导入已有视频。
- 叠影：默认优先检测红标记；没有明确红标记时使用完整物体的背景对齐与分离。默认覆盖整段视频，按固定间隔取约 12 个观察位置；可先圈选目标以减少其他区域的干扰。
- 轨迹：直接“找红点”，或点“标点”后点物体、拖动时间轴继续标记，再点“追踪”。非红色手动观察点仍可使用原颜色 / 纹理追踪；证据不足会停止，不编造后续路线。
- 默认隐藏点位时间、文件信息、参数表、说明段落和长期状态提示。右上角设置保留完整功能，下载图标保存当前画面。
- 叠影数量“少 / 中 / 多”、时间范围、间隔、双观察点、追踪算法、播放速度与视频/数据导出均在设置内。

## 慢动作与延时文件

- 慢动作以 **0.5 倍速**生成新视频，成片约为原片时长的 2 倍。网页会向相机申请最高 60 帧/秒，但这是期望值；实际帧率取决于设备、浏览器、光线和相机权限，不承诺真 60 帧/秒或系统相机级 120/240 帧/秒拍摄。
- 延时以 **8 倍速**生成新视频，成片约为原片时长的 1/8。它先录制原片，再本地转为快放成片，不是后台长时间低频采集模式。
- 变速通过本地视频解码、画布流和浏览器编码器生成可下载的新文件，不只是修改播放器速度。输出为浏览器支持的 MP4 或 WebM；编码期间应保持页面在前台。
- 变速成功后可以分别保存成片与拍摄原片；取消、编码失败或成片不能载入时保留原有视频。刷新页面前仍需主动下载。
- 叠影、轨迹和时间轴使用**当前成片时间**。若本页生成成片，原拍摄时间可近似换算为“成片时间 × 变速倍率”：慢动作乘 0.5，延时乘 8。CSV 同时提供成片时间和可还原的原拍摄估计时间。外部导入的已变速视频没有原始时间信息，不应凭播放时间推断真实运动速度。

## 课堂操作

1. 用系统浏览器打开 HTTPS 链接，允许相机。尽量固定设备，选择普通、慢动作或延时后录制 3—10 秒运动视频；可切换镜头。普通最长 60 秒，慢动作最长 20 秒，延时最长 120 秒，仅录画面。也可以导入 MP4 / WebM 等浏览器可解码的视频。
2. 停止录制后即可重播、慢放、拖动时间轴，或按设定时间步长前进 / 后退。变速模式会先生成新成片。网页不会自动永久保存录像，请及时保存需要的视频。
3. 在“叠影”可直接生成，或暂停在目标清楚的一帧后圈出红标记 / 物体，再生成。圈选帧可位于视频中间；程序从它分别向前、向后跟随。红点模式只叠红标记，完整物体模式只叠有图像证据的主体像素，均不复制整个选框。跟随会读取额外的中间画面，但这些画面只用于匹配，不会加入最终曝光位置。
4. 叠影设置支持开始、结束时间与等时间间隔。每次最多 60 个曝光位置，超限会提示，不会擅自改变间隔或补入不等间隔尾帧。配准、跟随或前景分离失败的时刻会跳过并提示；失败过多则停止生成。出现跳过时，图中保留位置**不再是连续完整的等间隔序列**，不应据相邻影像间距判断快慢。高级整帧叠加为明确选择的兼容模式，不会作为自动防抖失败后的隐蔽替代。
5. 在“轨迹”开启手动标点，点击物体上的同一观察位置。点击时暂停，拖动时间轴后继续标记；按时间顺序拟合路线，并显示运动方向箭头。
6. 也可点“找红点”自动建立起点，或从一个手动标记向后追踪，最长 30 秒。结果不可靠时停止；偏移处可手动补点后重新追踪。支持撤销及 A / B 两个观察点对照。
7. “保存画面”导出叠影或带路径的当前画面 PNG；可另存当前视频、拍摄原片与观测点 CSV。**不会导出烧录轨迹的新视频**，路径在网页播放过程中叠加显示。防抖叠影和原视频的坐标系不同，不把未经坐标变换的原视频轨迹直接画在防抖叠影上。

## 教学建议

- 先让学生预测，再拍摄真实运动，依据叠影和轨迹修正判断。
- A 点可放车身，B 点可放车轮轮缘。固定相机，相对于地面比较；一个点不能代表物体所有部分的运动。
- 实心点是人工标记，空心点是自动跟踪；手动点间的虚线是估计。平滑线是模型，不是新的实测证据。
- 等时间间隔取样不等于每一帧都被取到；浏览器按源视频帧率解码，实际帧时间有量化误差。逐步查看也是时间步进，不是专业逐帧剪辑器。

## 拍摄条件与边界

- 防抖用于校正有足够固定背景纹理的小幅平移、转动和缩放，不能代替固定设备。大幅机位变化、强视差、运动模糊、滚动快门或缺少背景纹理时会拒绝可靠配准；不要把拒绝提示当作“物体没有运动”。纯色背景无法证明相机是否移动；确认设备已固定时可关闭防抖再分析。
- 主体分离是配准后的背景估计与连通区域选择，不是语义 AI 抠图。透明瓶身反射/透过背景、手与物体相连、阴影、光照变化和多个运动物体仍可能影响轮廓。圈选能限制观察区域，但不能保证完整分离瓶子与手；封闭轮廓内的补孔不等同恢复真实透明度。
- 单一背景只根据实际看见的像素估计，不虚构被持续遮挡的背景，也不镜像填充防抖后的未知边缘。需要清楚背景时，拍摄中让物体经过不同位置，并尽量保持光照稳定。
- 本地追踪为颜色 / 纹理算法，不是云端大模型。醒目的小彩色贴点通常更容易追踪；快速运动、遮挡、出画、形变、转动或相似背景可能引发丢失或偏移，必须重播核对。
- 算法不会自动编造遮挡后的路线，需人工重新标点。两条轨迹的颜色为 A 红色、B 橙色。
- 推荐使用更新后的 Safari / Chrome / Edge。应用内置浏览器可能不开放相机；可先用系统相机拍摄再导入。实际兼容性仍受设备摄像头、系统权限和视频编码影响。
- 单文件下载后可尝试本地导入视频；相机权限通常需要 HTTPS / localhost，建议直接使用在线入口。

## 验证范围

已加入纯函数与流水线回归测试，覆盖已知相机变换、固定背景保留、等间隔采样、中段圈选的双向跟随、遮挡/失配后停止、无纹理拒绝、取消操作和内存上限；另用程序生成的课堂纹理、瓶子、手、红色干扰物和机位晃动视频检查表现。v3.1 增加灰桌面上的蓝色指尖陀螺测试片，覆盖快转、红色干扰、遮挡、机位偏移、反转与无红标记，并对用户提供的静态截图验证红贴纸检测。这些测试不是用户原视频或 iPhone 实机测试，不能证明所有真实拍摄条件、Safari 编码器和相机权限组合都已验证。上课前请在实际使用的手机上完成一次录制、回放、生成和保存检查。

## 隐私与保存

视频、像素和标记在当前浏览器内处理，不上传服务器；不调用外部 AI 服务，不录音。网页使用 CSP 禁止网络数据请求。网页资源本身仍由 GitHub Pages 提供。

刷新 / 关闭页面会丢失未保存的视频和分析结果。课堂拍摄尽量只拍实验器材与手部，避免不必要地记录学生面部与姓名。
