# 六上1.3 营养要均衡

用于六年级上册第一单元《健康生活》第3课的单文件互动课件。围绕“种类丰富，分量也合适吗？”开展探究，适合在真实饮食记录、食物卡分类和纸质膳食宝塔活动之后使用。

## 数字技术增加了什么

将混合菜肴拆成已知原料，追踪同一原料在不同餐次中的重复出现，自动汇总全天重量；保存原方案后调整食材量，观察参考标记的变化。学生能够把“吃了几道菜”“有多少种食材”“每类吃了多少”分开讨论，并用前后数据解释自己的调整。

## 两页功能

| 页面 | 操作 | 可获得的证据 |
| --- | --- | --- |
| 食物透视 | 选择早餐、午餐、晚餐或加餐中的菜肴；点餐盘或拖动滑杆展开；点原料追踪；清点全天原料 | 菜肴的示例配方、原料生重、跨餐来源、去重后的食物种数。例如鸡蛋同时出现在早餐和午餐，重量相加，种数只计一次。 |
| 调配一天 | 点选五层食物组（窄屏使用食物组选择框）；用滑杆或加减按钮调整全天原料量；保留原方案、前后比较、导出记录 | 各类当前量与教材参考带；原方案的棕色虚线标记；修改前后的原料明细与分类汇总。 |

调整全天某种原料时，系统按其当前配方占比分配到相关菜肴。第一次加入初始量为零的红薯时，它出现在早餐。返回“食物透视”可检查调整后的来源与重量。

“保留原方案”只保留一份快照；再次点击“更新原方案”会覆盖。 “恢复示例”会恢复初始配方并清除快照，需要保留的结果可先导出。

## 40分钟课堂建议

| 时间 | 实物与讨论 | 网页用途 |
| --- | --- | --- |
| 0—7分钟 | 用学生提前记录的一天食物或食物卡交流：菜名多就一定搭配合理吗？ | 暂不揭示统计结果，保留学生预测。 |
| 7—15分钟 | 对照真实原料或食物图片，讨论炒菜、盖饭中含哪些原料。 | 展开示例菜肴，追踪鸡蛋、大米等跨餐原料，区分重复次数与种数。 |
| 15—23分钟 | 阅读纸质膳食宝塔；用电子秤、原料样品感受不同重量，区分生米和熟米饭。 | 清点示例的一天，选择食物组，将数量与教材参考比较。 |
| 23—34分钟 | 小组提出先调整哪一类、理由是什么。 | 先保留原方案，再修改分量，切换前后比较；可尝试不同可行方案。 |
| 34—40分钟 | 用“我调整了……依据是……”交流证据，回到自己的真实记录提出一项改进。 | 导出小组示例记录；用仍未解决的差异继续讨论。 |

网页不要求整节课连续使用。个人饮食改进应结合家庭实际；一份示例菜单也不代表唯一合理方案。

## 模型与数据边界

- **已知配方示例**：“小禾的一天”由预设配方组成，不是学生实测记录，也不是从照片检测食材或营养。图中食物的大小、数量与宝塔层面积是示意，不承担称量功能。
- **13种不是评分**：初始菜单含13种非零食物原料，重复原料跨餐只计一次，油盐不计种数。增加或移除原料后种数会变化；种数不是健康分数，也不能单凭种数判断营养是否均衡。
- **统一重量口径**：以原料可食部分生重计；米饭按煮饭前的大米，黄豆按干豆，坚果按果仁，奶类按鲜奶当量。不能直接把熟米饭重量填入谷类生重参考。
- **全谷物是子集**：燕麦已计入谷类合计，“其中全谷物”不再重复相加。当前模型用燕麦呈现教材“全谷物和杂豆”这一子集。
- **日量和周量分开**：大豆参考105克/周、坚果50—70克/周。课件仅显示当天记录与周参考，不将一天的数据判定为周量是否达到。
- **不同参考含义不同**：奶类300克作为参考起点；盐少于5克是限制量；烹调油25—30克是参考量，不应为了进入参考带而额外加油。畜禽肉、水产、蛋、蔬菜、水果各自比较，不相互抵消。
- **参考带不是诊断**：各行采用独立刻度，只适合本类前后比较。教材参考针对11—13岁学龄儿童，实际需要存在差异，不要求每天精确一致；一天记录不能判断个人健康。课件不计算营养素含量、热量、健康分数或身高体重变化。
- **未模拟的内容**：饮水、运动、烹调损耗、食材营养成分差异及个体需要不进入计算。说明中保留饮水和运动提示，完整膳食讨论仍需结合这些因素。

## 离线使用和记录

下载本课完整HTML后直接用浏览器打开；样式、脚本与SVG食材图均在文件内，核心操作无需网络、账号或摄像头。来源链接需联网查看。

当前配方、原方案和清点状态使用当前浏览器的 `localStorage` 自动保存，不上传服务器、不跨设备同步。隐私模式、文件打开方式或浏览器设置可能限制保存；清理浏览器数据会删除记录。

“导出记录”生成带UTF-8标记的CSV，可用表格软件打开。内容包括原方案与当前方案的餐次、菜肴、原料、重量、分类参考和去重种数。导出是备份方式；当前版本不支持CSV导入。

## 素材与数据替换接口

### 食材图

`window.FOOD_ART` 以食材ID为键，值为适配 `viewBox="0 0 100 100"` 的SVG内部片段。保留现有ID和坐标范围即可替换图形；不需要把整张页面做成图片。

运行时可使用 `window.NutritionApp.replaceFoodArt(id, svgMarkup)` 替换食材图并刷新界面。组合菜肴中部分熟食形状由 `cookedPlate()` 绘制，精修成品餐盘时还需调整该函数。

### 配方与参考数据

`window.NutritionModel` 暴露 `foods`、`recipes`、`references`，以及 `initialPlan()`、`totalFood()`、`totalKind()`、`uniqueFoods()`、`setFoodTotal()`、`validatePlan()`。`window.NutritionApp.getPlan()` 返回当前配方副本。

建议在初始化前修改数据：`FOODS` 定义食材名称、类别和调量范围，`RECIPES` 定义餐次与原料克数，`REFS` 定义参考值与类型。新增食材还需同步 `FOOD_ORDER`、`GROUPS`、食材图及适用菜肴；不应只替换公开对象的整个属性后假定全部界面会自动重建。改变数据结构时应更新 `STORAGE_KEY`，避免读入旧记录。
